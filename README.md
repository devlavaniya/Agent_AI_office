# Intelligent Analytics Query Engine

A Streamlit implementation of the supplied "Build an Intelligent Analytics Query Engine" assignment.

## Architecture

```text
Natural-language question
        |
        v
+-------------------------+
| Streamlit UI            |
| - dataset loading       |
| - query input            |
| - result + feedback      |
+------------+------------+
             |
             v
+-------------------------+
| Context Builder         |
| - schema                 |
| - sample values          |
| - data dictionary        |
| - possible joins         |
| - prior feedback         |
+------------+------------+
             |
             v
+-------------------------+
| Gemini 3.8 Flash        |
| structured Pydantic JSON |
| -> executable SQL        |
+------------+------------+
             |
             v
+-------------------------+
| SQL Guard / Validator   |
| - SELECT/WITH only      |
| - rejects write/file ops|
+------------+------------+
             |
             v
+-------------------------+
| DuckDB execution        |
| sales_data + targets    |
+------------+------------+
             |
             v
Result + confidence + explanation
             |
             v
Feedback log -> future prompts
```

## Why this approach

The assignment explicitly allows SQL/Pandas/another executable form. This implementation uses SQL generated by Gemini and executed by DuckDB because:

- DuckDB is designed for analytical SQL and works in-process.
- The LLM handles natural-language interpretation, business terms, joins, grouping, ranking and nested analytical logic.
- The actual calculation is performed by a deterministic query engine, not by the language model.
- SQL is validated before execution and failed attempts are automatically repaired up to two times.

## Supported assignment requirements

- Natural language → executable analytical logic
- Business-term mapping using `data_dictionary.json`
- Aggregations
- Grouping
- Filtering
- Ranking / top-N within groups
- Contribution percentages
- Nested logic / CTEs
- Target comparisons between `sales_data` and `targets`
- Time-based analysis
- Confidence score from 0 to 1
- Explanation of interpretation and logic
- `feedback_log.csv` context
- No hardcoded answers
- Unseen queries through schema-driven prompting

## Setup

### 1. Create a virtual environment

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 2. Install dependencies

```powershell
pip install -r requirements.txt
```

### 3. Set Gemini API key

Recommended for local development:

```powershell
$env:GEMINI_API_KEY="YOUR_GEMINI_API_KEY"
```

Or enter the API key in the sidebar at runtime.

For Streamlit deployment, use a secret named `GEMINI_API_KEY`.

### 4. Put the assignment files in `dataset/`

```text
dataset/sales_data.csv
dataset/targets.csv
dataset/data_dictionary.json
dataset/nl_queries.json
dataset/feedback_log.csv
```

Only the first two are required. The other files improve semantic mapping and the feedback loop.

### 5. Run

```powershell
streamlit run app.py
```

## Example query patterns

The model is instructed to handle questions such as:

- "What was total revenue by region?"
- "Show the top 3 products within each region."
- "What percentage of each region's revenue came from its top product?"
- "Compare actual sales with targets by month."
- "Which regions exceeded their target and by how much?"
- "Show the monthly trend for the last 12 months."

These are prompt examples only; the application does not hardcode any answer.

## Security / reliability notes

1. Do not put the API key in source code or commit it to Git.
2. The model receives schema, small samples, dictionary context and recent feedback—not the entire dataset.
3. SQL is restricted to read-only `SELECT`/`WITH` statements.
4. File-reading and system/catalog functions are rejected.
5. SQL is first explained/validated by DuckDB and then executed.
6. If a generated query fails, Gemini receives the error and is asked to repair the query, up to three total attempts.
7. The confidence score is model-generated and should be treated as a calibrated signal, not a proof of semantic correctness.

## Important limitation

The supplied assignment file describes the required files and behavior, but the actual `sales_data.csv`, `targets.csv`, and `data_dictionary.json` files were not supplied with the document in this chat. Therefore, the code is schema-driven and does not hardcode column names. Once the real dataset is placed in `dataset/` (or uploaded through the UI), Gemini receives the real schema and dictionary and can generate queries against it.
